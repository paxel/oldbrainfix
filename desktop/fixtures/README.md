# Fixture corpus

Generated by `packages/oldbrainfix_core/tool/gen_fixtures.dart` from the Dart core; the desktop core loads every `log.jsonl` and must read the same `expected.json`. Do not edit by hand.

- `schema.sql`: the tables and indexes of the store.
- `signing.json`: entries signed by the writer key, with the bytes the signatures cover.
- `question_marks.json`: the background's shapes and their scatter over a region.
- `schedules.json`: RRULEs read, written back or refused, schedules with their Occurrences, days normalised, and the instants of wall-clock times around daylight-saving switches in Central Europe.
- `routines/alarms.json`: the Agenda, alarm plan, Missed Summary and Nudge of the `routines` log at held moments with this Device's settings, on the same clock.
- `pair_codes.json`: pair codes for a QR and for typing, codes as typed, and what is no code.
- `keys.json`: the writer's key record, and another key claiming its device.
- `sync/`: two Devices that met once and wrote more since: their logs (`host.jsonl`, `joiner.jsonl`) with their blobs and the keys they hold (`settings.json`), the host's vector, the joiner's `POST /sync` request (with its proof for the PIN 246810) and the host's answer, both with the Area keys, the own Profile and its backup key, the backup key each then holds, the host's on both (`backup_keys.json`), the own Profiles both hold after it, the host's named by the user and taken over by the joiner, whose own still had the defaults (`profile.json`), and what both read after the joiner took it in (`expected.json`).
- `conflicts/`: two Devices that met once, then edited the same Note text, Area name and Routine schedule apart, wrote the same value on both sides and renamed a Topic on one side only: their logs, the session between them, the Conflicts both find (`expected.json`), the host keeping the older version of each (`picks.jsonl`, at the held clock), and what both read after a second session.
- `crypto.json`: messages sealed with XChaCha20-Poly1305 under given keys, nonces and what they are bound to; a key's id; a blob's name in the shared folder.
- `folder/`: two Devices that met once, so the joiner holds the host's keys; the host wrote more since, a new Area among it, and synced through the shared folder: both logs with their blobs and the keys each holds (`settings.json`), the folder the host wrote (`oldbrainfix-sync/`, nonces counted from 1001 on; its keys file carries the own Profile, renamed since they met, and its backup key), what the joiner reads from it and the backup key it holds then (`expected.json`) and its own Profile after (`profile.json`).
- `bundle/`: two Devices that met once; the host wrote more since, a new Area among it, and a bundle for the joiner: both logs with their blobs, the keys each holds and what each was told the other holds (`settings.json`), the bundle (`host.obfsync`, nonces counted from 2001 on), what the joiner reads from it (`expected.json`) and its own Profile after, both Profiles named by the user since, so "Which one is you?" waits (`profile.json`). The desktop core compares the files inside the zip byte for byte, not the zip itself, whose headers its zip library writes its own way.
- `shared/`: Ann shares a Starter Set Area with Ben as a Member: her log before (`before.jsonl`), what sharing wrote (`share.jsonl`, ids counted from 0x101, at a held clock), Ben's log (`joiner.jsonl`), the invite session (`request.json`, `answer.json`) with the Profiles each then keeps, Ann renamed and publishing the Area's Profiles into a shared folder (`<device>.<key id>.profiles`, nonces counted from 2000) and what Ben keeps after reading it, what Ben wrote, allowed and not (`member.jsonl`), Ann filing a Note in (`owner.jsonl`), the paired session after (`request2.json`, `answer2.json`), Ben made Manager (`role.jsonl`) and writing as one (`manager.jsonl`), then removed (`remove.jsonl`) with the answer he gets then (`answer3.json`), and what both read, which entries the roles leave out and whose Profile marks each Note (`expected.json`).
- `sent/`: Ada sends a Note with a Section, a Routine and a Reminder to Ben: her log (`sender.jsonl`), her Profile's settings, which every file she sends carries (`settings.json`), what sending wrote (`sent.jsonl`, ids counted from 0x301, at a held clock), the file signed only (`signed.oldbrain`) and encrypted to Ben's X25519 key (`sealed.oldbrain`, random bytes counted from 4001 on), what Ben accepting wrote (`accepted.jsonl`, ids counted from 0x401), keeping her Profile; then Ben makes it his own (`receiver.jsonl`, from 0x501), Ada changes it (`changed.jsonl`, from 0x601), renames herself and sends an update (`update.jsonl`, `update.oldbrain`), which Ben applies after comparing her short code (`updated.jsonl`, from 0x701); Ada cancels it (`cancel.jsonl`, `cancel.oldbrain`), Ben accepts that (`cancelled.jsonl`), and refuses a cancellation another key signed (`forged.oldbrain`) and a file whose Profile is not bound to the key that signed it (`impostor.oldbrain`); what he reads and the Profiles he keeps at each step (`expected.json`).

- `profiles/`: Profile names as typed and as kept, initials, placeholder colours, short codes from an id and a first key, records as they are written and records refused, the own Profile's local settings after each step (ids counted from 1), signed Profiles another of the own Devices sends with what became of each and the settings after (`takes`, ids counted from 0x65), Profiles of another person taken by a Device that keeps one with what became of each and what it keeps after (`people`), and a Profile picture made here (`picture.jpg`).
