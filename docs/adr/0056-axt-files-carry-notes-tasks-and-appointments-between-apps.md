# AXT files carry Notes, Tasks and Appointments between apps

Old Brain Fix exchanges records with other small apps over AXT, the open standard for typed records (https://github.com/paxel/axt), through files in both directions on the phone and the desktop (obf-1144, Q1 (a) to Q3 (a)). The local network and the relay wait until the libraries have them. Both cores use the AXT libraries, `axt_protocol` 0.2.0 (Dart) and `axt-protocol` 0.1.1 (Rust), both conforming to AXT 0.2.0 with the file transport, through their public API only: neither core builds an AXT message itself (`axt.dart`, `axt.rs`).

## What a Note goes as

A Note goes as an AXT `Note` (`axt.example.v1.Note`), a Note with a Reminder or Routine as a `Task` (`axt.example.v1.Task`), version 1 of each (Q2 (a)).

- **Note.** `title` is the first line of the text as it reads, trimmed. `text` is the whole text as it shows (ADR 0035: each Box in the glyph of its state, without its id), `format` `MARKDOWN` for a Formatted text and `PLAIN` for every other, a Code text included. `tags` are the Tags of the text without their `#`, each once whatever its case, in their order, as written (ADR 0032). `created` is the capture time, `updated` the latest entry of the Note and of its Routines, both as instants in `Etc/UTC`.
- **Task.** `title` as above, `notes` the lines after the first as they read, plain. Of several Routines and Reminders the one whose first Occurrence comes first goes, by id when two start alike. `due` is its first Occurrence as a floating wall clock (ADR 0006), `due_all_day` true for one without a time. `repeat` is its RRULE as the calendar file writes it (`ics.dart`): several times of day go as `BYHOUR` and `BYMINUTE` where every hour with every minute named gives exactly those times, such as 08:00 and 20:00; otherwise the Task keeps the first time and a `COUNT` becomes the `UNTIL` of the last Occurrence. An `UNTIL` takes the type of `due`. `done` and `done_at` say whether the first Occurrence is Done and when, as AXT says the Occurrence at `due` is. `priority` is `NONE`.
- **Id and version.** The record id of a Note's `Note` is the Note's id as a UUID of version 4: its 32 hexadecimal digits with the bits of the version and the variant set; an id of another form, such as a help Note's, through SHA-256 first. A record keeps its type for its whole life and a receiver refuses another type under its id (`TYPE_CHANGED`, AXT `spec/records.md`), so the Note's `Task` has an id of its own, the same through SHA-256 with the type's name. So a second file of the same Note is an update of the same record, also after a Box ticked, an Occurrence Done or a Routine trashed. The version is the library's: a state stamp (AXT `spec/sync.md`, section 2.2) on the store's clock as the file is written, above every version a file of the same Device gave the record before, whatever changed. The ticket's "version = its latest change" is met as far as the library lets an app: it gives no record a version of the app's choosing, and a Note's latest entry does not rise when a Routine of it is trashed or a change dated earlier comes in by sync.
- **Changing type.** A Note that gains its first Reminder goes as its `Task` from then on, and one that loses its last as its `Note` again. The other record stays where it was taken; this version sends no deletion of it, which is obf-1147's to decide.
- **What does not go.** Sections, the Lines of a Checklist or Shopping List, a Tally's fields and entries, photos, recordings and attached files, the Routines and Reminders but the one that goes, a Routine's later times of day where `BYHOUR` and `BYMINUTE` cannot say them, Heads-ups, Frogs, Importance and the Capture Context stay behind: the example types have no fields for them. A Pack carries them between two Old Brain Fix users (ADR 0043).
- **Manifest.** Every file carries Old Brain Fix's manifest: it takes `Appointment`, `Task` and `Note` from version 1 on, each with a purpose sentence in English and German, takes no other type, and sends `Note` and `Task`.

## Signed by this Device

Each Device signs with the Ed25519 key it already has, made at install and bound to its device id (ADR 0002, Q3 (a)); the library gets its seed and the Device's X25519 key of ADR 0015 as its encryption key, which it does not use for files.

The Profile's Devices are meant to be one AXT sender: the Profile's first key and the keys joined to it (ADR 0017) are what AXT calls a device set, its first key and the keys added to it. A file of a set begins with its chain of `DEVICE_ADD` messages, each signed by a key of the set over the new device's proof (AXT `spec/keys.md`, sections 5.2 and 5.4). Neither library offers a way to write such a chain yet, and the Profile's key statements sign other bytes, so each Device's files are those of a sender of its own for now. When the libraries can write a chain, the binding statements of the Profile become `DEVICE_ADD`s made at Pairing; until then another app meets the phone and the desktop as two senders.

## Reading is applying nothing

Opening a file reads it with a library instance of its own on a store in memory, with a key of its own and a manifest that takes every type, so that a record of a type not taken is still named: the library checks the file as a whole, signatures and all, and hands back each record message with its id, version and what it made of it (`APPLIED`, or why not). Each record shows once, as its last message the library applied leaves it, where that message lies: a later version of the same id in the same file replaces the earlier one, and a deletion after it leaves nothing to take. A file the library rejects as a whole is `NotAnAxtFile`. Nothing is kept: reading the same file again reads the same, and the sender stays a first contact. The core says the sender's key, its short fingerprint to compare, the app name its manifest gives, and whether the key is one of the user's own Devices', by the device id it makes (ADR 0002) as the user's own Devices are known.

Each `Note`, `Task` and `Appointment` that came in whole is a Note to take; every other record, a deletion, a withdrawal or one the library refused is listed as not taken, with its type where it has one.

- **Note.** Its `text` in its format, `MARKDOWN` as a Formatted text and `PLAIN` as plain; its `title` as its first line unless the text begins with it; its `tags` not in the text yet on a last line, each part between `/` as an Import makes a label a Tag (`TextTags.fromLabel`, nested again by `/`).
- **Task.** Its `title` and `notes` as lines of a plain text. With a `due` it is a Reminder at that wall clock, all day for `due_all_day`, repeating by `repeat` where the core reads the RRULE (ADR 0006) and once where it does not; `done` makes its first Occurrence Done at `done_at`, or when it is taken.
- **Appointment.** Its `title`, `location` and `notes` as lines of a plain text, and a Reminder at its `start`, all day for `all_day`; its `end` is not kept. Each of its `reminders` before the start becomes a Heads-up (ADR 0052) in whole minutes, an all-day one in whole days; one at or after the start, one in months or of seconds, and one further ahead than 30 days are left out.
- **Times.** A zoned `due` or `start` is put on this Device's wall clock through its instant; a floating one is taken as it reads.

## Taking

Taking writes the chosen records in one batch, in the file's order, each a new Note of this Device's captured now, in the Area or Topic chosen or in Unsorted. A Reminder or Routine is written, not spawned, as a Sent Item's is, so a Note in Unsorted stays there; its Heads-ups are the taker's own; its first Occurrence Done as the record says. A place that is no Area or Topic, one where this Device may not write, or one where it may not make Reminders and Routines is refused before anything is written.

Each Note taken keeps where it came from in the field `axtFrom`: `{"id":…,"sender":…,"type":…,"version":…}`, keys sorted, the record's id as its sender wrote it, the sender's key in hexadecimal digits, the record's type and the version taken. It is a field of the Note, so it syncs with it. It counts only when one of the user's own Devices wrote it, read as the person's settings are (ADR 0040, `currentByOwn`, `own_current`): what another person's Device in a Shared Area writes there is ignored, as `packFrom` is (ADR 0043), so nobody can make a Note of theirs pass for an update target of another app's record. Applying later updates and deletions of a record is obf-1147's; this field is what it applies them by.

## The AI port

`read_note` names under `axtFrom` where a Note taken from an AXT file came from, read as the app reads it, so another person's write does not show either. No tool writes it or reads, writes or takes a file (ADR 0026): opening a file is a person's own act with the system's share sheet or picker, as a Pack's is.

## Considered

- Keeping the library's state in the store, its own versions and the senders accepted (rejected for now: a stamp on the store's clock rises from file to file without it, the manifest's content is fixed in this version so its revision stays 1, and the senders a file is accepted from need the user's word once obf-1147 applies updates; a Backup would have to carry it too). A Device whose clock is set back gives versions below those it sent before, which a receiver takes as stale until the clock passes them again.
- The latest change of the Note as the version's clock (rejected: it does not rise when a Routine of the Note is trashed, nor for a change another Device dated earlier, so a receiver would keep the old record as newer).
- One record id for a Note whatever it goes as (rejected: AXT refuses a record whose type changes, so a Note that gained a Reminder could never be updated).
- Reading a file with the store's state, so that the library knows a sender after the first file (rejected: applying is the library's only way to hand out a file's records, and opening a file to look at it must keep nothing).
- One `Task` for each Routine of a Note (rejected: the record id is the Note's, so a Note is one record).
- Writing Old Brain Fix's own types as extensions, so another Old Brain Fix takes back what the example types cannot say (left for later: a Pack carries everything between two Old Brain Fix users).
- Building the `DEVICE_ADD` chain in the cores (rejected: it is AXT's own message, and the cores use the libraries' public API only).

## Consequences

- Both cores write the same records and read the same Notes; the files' bytes differ, as the library draws its sync marker and the low bits of each version at random. The `axt` fixture therefore keeps the files outside the corpus the generator writes anew, beside the desktop core's fixture test (`tests/axt/`): `from-dart.axt` and `catalog.axt` written by the generator with `UPDATE_AXT=1`, `from-rust.axt` by the desktop core's test when it is missing or with `UPDATE_AXT=1`. The corpus holds Ada's log, the fingerprints of the three types, the manifest, each Note's record id and record, each file read by Ben, the entries of his taking them, and another person's `axtFrom` that counts for nothing. Both cores read all three files to the same Notes.
- The Dart library ships the example types as classes without their descriptions, so the Dart core keeps the three descriptions (`axt_types.dart`, CC0 1.0); the fixture pins their fingerprints to the Rust library's.
- New dependencies: `axt_protocol` with `avro` (Apache-2.0 OR MIT), `timezone` (BSD-2-Clause) and `http` (BSD-3-Clause); `axt-protocol` with `apache-avro` (Apache-2.0) and second majors of `ed25519-dalek`, `curve25519-dalek` (BSD-3-Clause), `sha2`, `digest` and `rand_core`, and `x25519-dalek` (BSD-3-Clause). `avro` needs `archive` 4.7.1, which writes an extended timestamp into the central directory of every zip: the Dart core's bundles and the office files the generator makes as inputs change in their headers, not in what they hold, and the desktop core reads them as before. `axt-protocol` needs Rust 1.100.
