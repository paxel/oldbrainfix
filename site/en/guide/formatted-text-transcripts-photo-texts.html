A Note's text can be formatted, be code, and hold tables, boxes and #tags. Voice recordings get a Transcript and photos a Photo Text, both written on the Device; the search finds Notes by all of them. Each box below shows the steps on the phone and on the desktop.

The desktop app does the same with the mouse and the keyboard. A Note opens in the Note dialog with a double-click on its card; the format bar sits above the text field; a table full screen takes Tab and Shift+Tab to the next and the previous cell; and the search field sits above the list of Notes. The details of each box say where the desktop differs.

Format a Note's text

Make words bold, italic or a heading, or make a list, quote, link or code.

  • Long-press the Note's card.
  • Select the words to format.
  • Tap Bold or another button on the format bar.
  • Tap Back.
    •
  • Double-click the Note's card.
  • Click into the text.
  • Select the words to format.
  • Click Bold or another button above the text.
  • Click outside the text.
    •

    The text of a Note and of a Section can be bold, italic or struck through, have two heading levels, bulleted and numbered lists one level in, quotes, links, inline code, code blocks and tables. It is kept as Markdown, exactly as written. A text stays plain until it is first formatted: by a button of the format bar, by a format typed as Markdown, by pasting a text that uses one, or by Formatted text in its Text format badge. A formatted text does not become plain again directly; it can become Code, and Code can become plain (see "Keep a script as code"). Cards, Sections, Sent Items and Backups show it formatted. A Device with Old Brain Fix 0.1 shows the Markdown and cannot change it.

    The format bar.

    The format bar is there in Advanced. In Simple a field has none, while typed Markdown still formats and a formatted text shows formatted.

    On the phone, the format bar sits on the keyboard while the Note editor or Add to Note has it open, and the quick note where Settings under "Quick note" switch on Format bar, a switch shown in Advanced and off at first. Its buttons, in this order:

    • ☐: Put in ☐ at the cursor (in the Note editor and in a table's cell; not in Add to Note or the quick note; see "Tick a box in the text").
    • Bold, Italic and Strike through.
    • H1 and H2: Large heading and Small heading.
    • Bulleted list, Numbered list and Quote.
    • Link, Code and Code block.
    • Indent list item and Move list item out.
    • Table.

    The buttons that find no room go into ⋮ at the end of the bar, More formats, which opens at the finger. Bold, italic, strike-through and code work on the selection, or on the word at the cursor when nothing is selected; the line formats work on every line the selection touches. A button shows highlighted while the cursor is in its format. A second tap takes the format off again, except for Link, which asks for the address again, and Table, which opens the table; Indent list item and Move list item out each move the item one way.

    With Type in two rows on, the default in Settings under "Typing", the top row shows the text formatted, its Markdown marks left out, and the row above the keyboard shows the Markdown of the cursor's line, with ◀ and ▶ to move the cursor. With it off, the field shows the marks dimmed. The quick note always types in one row.

    Typing Markdown. A format typed as Markdown takes effect as it is typed:

    • At the start of a line, followed by a space: # for a large heading, ## for a small one, -, * or + for a bulleted item, 1. for a numbered item and > for a quote.
    • Within a line: **bold**, *italic* or _italic_, ~~struck~~, `code` and [label](address).
    • On a line of its own: ``` or ~~~ opens a code block, and the same fence on a later line closes it; typing the closing fence makes a plain text formatted.

    Every line break shows as one, so lines typed one under the other stay apart. An item indented by two spaces or more is one level in; deeper items show one level in. Numbered items that follow one another count on, so 1. on every line shows 1, 2, 3. Deeper headings (###), images and other Markdown show as written.

    On a capture screen without the format bar, a text typed or pasted with Markdown is saved as a formatted text.

    Code blocks.

    A code block is the lines between two fences of three backticks, ```, or three tildes, ~~~, each fence on a line of its own. It shows in a fixed-width font on a grey ground, its lines exactly as written: nothing in it is a format, a table, a #tag or a box. A word after the opening fence, such as ```bash, names the language; it is kept in the text but does not show. A block ends only at a fence of the same character at least as long as the one that opened it, so in a block opened with four backticks a line of three is a line of the block. Without a closing fence the block runs to the end of the text.

    Code block in the format bar puts the lines the selection touches into a block, an empty one at an empty line; in a block it takes the block's fences off. Its fences are longer than any run of backticks inside. On a compact card a code block shows its lines without the fences.

    Links.

    Link asks for the "Web or e-mail address", the one there already filled in; Set link puts it on the selection or the word at the cursor. Leave it empty to remove the link. An address typed without "https://" is taken as a web address, or as an e-mail address when it holds an "@" and no "/". A tap on a link on a card opens it in the browser or the mail app. Only web and e-mail addresses open; any other link, which may come from another person in a Shared Area, stays text.

    A web address written into any text, plain or formatted, that starts with "http://" or "https://" is a link too: a tap on it opens it in the browser, and a tap beside it or a long press does what it does on the card. Punctuation right after it, such as a full stop, a comma or a closing bracket, is not part of it; "www." alone is no link. An address in code, a code block, a Code text or a link stays as written. The text itself is not changed.

    On the desktop.

    • The format bar sits above the text field of the Note dialog, with the same buttons; each shows its name as a tooltip. Buttons that find no room go onto a further line. Ctrl+B and Ctrl+I are bold and italic while typing.
    • A right-click on words selected in a formatted text offers the format bar's Bold, Italic, Code, Link and Code block for them, below Cut, Copy, Paste and Select all.
    • A formatted text shows as it reads; a click on it edits its Markdown, the marks dimmed. Leaving the field or Ctrl+Enter saves it.
    • Add to Note has the format bar too, without ☐, which only the Note's text puts in; a table edited from it full screen goes back into the field, and nothing is kept before Add to Note.
    • Link opens a dialog with the same field; Enter or Set link takes it. A click on a link opens it in the browser or the mail program; the mouse over it shows its address. A web address written into a text opens on a click too.

    Keep a script as code

    Show a Note's whole text exactly as written, such as a script.

  • Long-press the Note's card.
  • Tap the Text format badge.
  • Tap Code.
    •
  • Double-click the Note's card.
  • Click the Text format badge.
  • Click Code.
    •

    A plain Note's whole text can be code, such as a script: it shows exactly as written, in a fixed-width font on a grey ground, without wrapping its lines. Nothing in it is a format, a table, a #tag or a box. In the Note editor a long line moves sideways under the finger; on a card it is cut off at the edge, and the editor shows it whole.

    • The Text format badge in the Note editor shows the text's format and switches it between Plain text, Formatted text and Code. A formatted text can become Code, its Markdown kept as written, but not plain again directly; a Code text can become plain or formatted. The badge shows for a Plain Note.
    • When a text pasted into the Note's text looks like a script or code, the editor says "This looks like code." under the text with Keep as code; the cross lets the paste be. Such a paste does not format the text. A text looks like code when it starts with #!/, or when at least half of its three or more lines end in ;, { or }, start with }, or are indented by a tab or four spaces without starting a list item. Capture never asks.
    • A Code text has no format bar and no ☐. Its ☐ stays a character; a box of a text made Code keeps the state it shows as its character.
    • Search finds the words of a Code text as written. Share and Copy text give it as written.
    • A Note whose text is Code is no Checklist, Shopping List, Tally or Session; its Kind badge only shows it until the text format is changed back.
    • The Note's History lists each change of the text format.

    On the desktop the Text format badge sits among the Note dialog's badges and opens a dialog with the three choices. A Code text scrolls sideways with Shift and the wheel or its scroll bar; "Keep as code" shows under the text after a paste that looks like code.

    Put a table in a Note

    Keep rows and columns, such as meter readings, in a Note's text.

  • Long-press the Note's card.
  • Tap where the table should go.
  • Tap Table on the format bar.
  • Type into each cell.
  • Tap Back.
    •
  • Double-click the Note's card.
  • Click where the table should go.
  • Click Table above the text.
  • Type into each cell; press Tab for the next.
  • Click the arrow at the top.
    •

    In the text, a table is drawn as a grid, made smaller to fit the width, its header row in bold. A tap on it opens it full screen. Table in the format bar opens the table the cursor is in; elsewhere it puts a new table at the cursor, two empty columns with a header row and one more row, on lines of their own, and opens it with its first cell being edited.

    • Full screen, the header row stays on screen while the rows scroll up and down, and so does the first column while it holds headings. A table wider than the screen moves sideways with a one-finger drag on its cells or by the bar above it, Move the table sideways; this is the only place where a sideways swipe does not go back or forward.
    • A tap on a cell edits it in place, framed, with the format bar of ☐, bold, italic, strike-through, link and code. A cell holds one line; ↵, a tap on another cell or on the space around the table, or Back writes it.
    • A tap or long press on a row's number opens Insert a row above, Insert a row below, Move up, Move down and Delete row at the finger; a column's letter opens Insert a column to the left, Insert a column to the right, Move left, Move right and Delete column, and for column A the switch First column as headings.
    • The empty row under the table (+) and the empty column beside it add a row or column once words are written into them.
    • Deleting a row or column that holds words asks once, "Delete this row?" or "Delete this column?": "The words in its cells are deleted from the Note." Deleting the last row or column deletes the table, and asks "Delete the table?".

    On the phone, the fields of a formatted text show a table as the same grid, never as its Markdown; a tap on it opens it full screen, and what changes there comes back into the field. The cursor passes a table as one block: ◀, ▶ and the arrow keys go from right before it to right after it, and the row above the keyboard shows it as a table sign. What is typed right before a table goes on a line of its own, and what is typed right after it goes under it with a blank line between. Backspace right after a table, or deleting a selection that holds one, deletes the whole table, and asks first while its cells hold words.

    Tables are written as GFM tables: each edit writes the whole table anew, every row as | a | b |, and leaves the words in its cells as they were. On the desktop, a line typed right under a table's Markdown, without a blank line between, becomes a row of it. Markdown tables pasted in become tables. Where you may only read the Note, the table opens to read.

    On the desktop the field being edited shows a table's Markdown; the table opens full screen from the text as it reads, with a click, or with Table while the cursor is in its Markdown. Full screen it scrolls with the mouse wheel, Shift and the wheel, or the scroll bars. A click on a cell edits its words, framed, without a format bar: Enter or a click elsewhere writes them, Tab goes on to the next cell, Shift+Tab back, and Esc leaves the cell as it was. The rows' numbers and the columns' letters open their menus on a click or a right-click. Alt+Left, the mouse's back button, Esc or the arrow at the top leave the table.

    Tick a box in the text

    Mark a point in a text as done or failed, such as "✅ v2 supported".

  • Type ☐ in the text, or tap ☐ on the format bar.
  • Tap Back.
  • Tap the ☐ on the Note's card.
  • Tap Check, Fail or Open.
  • Tap the box again, then History.
    •
  • Type ☐ in the text, or click ☐ above the text.
  • Click outside the text.
  • Click the ☐ on the Note's card.
  • Click Check, Fail or Open.
  • Click the box again, then History.
    •

    A ☐, ✅ or ❌ anywhere in the text of a Note or a Section is a box: open, checked or failed, such as "✅ v2 supported at the customer". It becomes a box when the text is saved, and the character it was written with is the state it starts in. A tap on it opens a menu at the finger with Check, Fail and Open, the current state left out. The choice is kept beside the text with who made it and when, synced to every Device; the text itself stays as it is.

    • A box can stand in the middle of a word or line, in a list item, a quote, a link's words and a table's cell. In inline code, a code block, a link's address or a web address it does not; nor do other boxes and ticks such as ☑ or ✓.
    • Boxes are ticked on the Note's card, in its Sections, in the Note editor and in a table full screen. A box being typed can be ticked once the text is saved.
    • ☐ in the format bar puts ☐ in at the cursor, also in the middle of a word.
    • Each box carries an id that is never seen. The cursor steps over a box as one character; deleting the box's character deletes the box.
    • Show ticks, in the ⋮ of the Note's card and as a badge in the Note editor while the Note or a Section holds a box, shows after each ticked box, small and grey, who ticked it last and when, such as "Ann, Tue 14:02", or "You" for your own ticks; an older tick shows its date. It is kept for that Note on that Device.
    • Once a box has been ticked, its menu also has History: every change, the oldest first, with its state, who made it and when.
    • In a Shared Area everyone with a role there ticks every box of every Note and Section. Adding, moving and deleting boxes is an edit of the text, which stays with the Note's author and the Managers. A Note in the Trash is not ticked; where you may not tick, the menu of a box ticked before holds only History.
    • Copies, shares, Markdown files and Sent Items show each box in its state now.

    On the desktop a click on a box opens its menu under it, also in the field being edited: ☐ Open, ✅ Check and ❌ Fail, the current state left out, and, once it has been ticked, History. In the field being edited the arrow keys step over a box as one character, and Backspace after it or Delete before it removes it with its id. Show ticks is in the card's ⋮ and, in the Note dialog, a badge with a switch.

    Find Notes by a #tag

    Mark Notes with a word such as #garden and find them all again.

  • Type # and a word into a Note's text, such as #garden.
  • Tap the #tag on a card.
    •
  • Type # and a word into a Note's text, such as #garden.
  • Click the #tag on a card.
    •

    A word with "#" in front, such as "#garden", is a tag and is drawn in the accent colour, on cards, in Sections and in the editor. A tap on it on a card, in a Section or in a table opens the search of all Notes with the tag as written. Nothing is stored for a tag, and there is no list of tags; it is a word of the text. Typing the tag into the search finds the same.

    • A tag is made of letters, digits, "_" and "-", and holds at least one letter: "#to-do" and "#v2" are tags, "#126" is a number.
    • "# Title" with a space, "C#" and the "#" in a web address are no tags. In a formatted text, a "#word" inside code, a code block or a link's address is none either; nor is any in a Code text.
    • The search for "#garden" finds every Note holding it in any case, also "#gardening", which begins with it, but not the word "garden" without "#".

    On the desktop a tag's click closes the Note dialog and searches all Notes, as on the phone; in the field being edited it places the cursor.

    Get the words of a voice recording

    Let the app write down what a voice recording says, as its Transcript.

  • Tap your Profile picture, then Settings.
  • Tap Speech model.
  • Tap Base, 148 MB.
  • Record a voice Note.
    •
  • Click Edit ▸ Settings….
  • Click Base, 148 MB under "Speech model".
  • Record a voice Note.
    •

    A voice recording gets a Transcript: the words recognised in it, kept next to the recording. Whisper writes it on the Device, in English or German, whichever the recording sounds more like, in the background and one recording at a time once the Note is saved; recordings captured before the speech model was there follow. While it runs, "Transcribing…" shows under the recording; a recording without speech shows "No words heard.". The recording is always kept.

    Whisper is led in with your Area and Topic names; for German speech also with the English words German is full of and the app's words, such as Unsorted, Routine and Agenda, so that they are written as they are spelt. Where Whisper only repeats that lead-in, or a run of three or more of those names, the repeat is taken out of the Transcript.

    The speech models.

    Transcripts need a speech model, downloaded once. The phone offers it after the first start (see Getting started); Settings, Speech model offers it on the phone and the desktop at any time. Under "Model":

    • Base, 148 MB: faster, and enough for English or German alone.
    • Small, 488 MB: better with English words in German speech, but slower, and it needs more memory.

    Choosing a model downloads it, with its progress and Cancel. Only the chosen model is kept: the one before is deleted once the new one is in place. Each download comes only from Old Brain Fix's own release on GitHub and is checked against a fixed checksum before it is used; a download that broke off or did not match keeps nothing and says so. Use a file of my own takes whisper.cpp's multilingual ggml-base.bin or ggml-small.bin from the Device, known by its checksum, whatever the file is called; any other file is rejected.

    On the desktop the speech model is a card in the Settings dialog, after "Quick note", with the same choices; Transcripts work the same, while the app runs.

    Get the text of a photo

    Let the app read the text on a photo, such as a receipt, as its Photo Text.

  • Tap + on the Agenda.
  • Tap Photo or Gallery.
  • Take or pick the photo.
  • Tap 10 min, 30 min or 1 h.
  • Read the Photo Text under the photo on its card.
    •
  • Press Ctrl+N, or click File ▸ New Note.
  • Click Paste or From file… for the photo.
  • Click 10 min, 30 min or 1 h.
  • Double-click the Note's card.
  • Read the Photo Text under the photo.
    •

    A photo or a picture gets a Photo Text: the text recognised in it, kept next to the photo. RustO reads it on the Device with PaddleOCR's PP-OCRv6 Tiny models, which are part of the app, so nothing is downloaded and nothing leaves the Device. It reads German letters (ä, ö, ü, ß) and €, and keeps the lines as they are laid out on the photo, so a price stays on the line of its item. A strongly curved page can lose some of its lines. Photos are read in the background, one at a time, once the Note is saved; capturing never waits for it.

    In a card's detailed view, Transcripts and Photo Texts show dimmed under the word "Transcript" or "Photo Text". The compact view of a Note without words shows the first three lines of its Transcripts, and of the Photo Texts of photos that were removed; a photo still there shows as a small picture.

    On the desktop Photo Texts work the same, while the app runs; the Note dialog shows each one under its photo.

    Use or remove a Transcript or Photo Text

    Take a Transcript or Photo Text into the Note's text, or remove it.

  • Long-press the Note's card.
  • Tap Replace Note text or Append to Note text.
  • Tap Remove generated text instead.
    •
  • Double-click the Note's card.
  • Click Replace Note text or Append to Note text.
  • Click Remove generated text instead.
    •

    Only the app writes a Transcript or Photo Text; it cannot be edited. In the Note editor, under each Transcript and Photo Text, also those of a merged Note's Section:

    • Replace Note text makes it the text; Append to Note text adds it on a line of its own after the text. Under a Section's Transcript or Photo Text they change that Section's text. The text is then edited as usual. Into a formatted text it goes as plain text, written so that it reads as itself. Both show while the generated text has words and the text may be changed.
    • Remove generated text asks once ("Remove this Transcript?" or "Remove this Photo Text?"): the search no longer finds the text, on all your Devices, and the recording or photo stays, so the text can be made from it again. The text of a recording or photo that was removed cannot be removed; it is all that is left of it.
    • Transcribe again and Read the text again make the text anew from the file, in place of the one before or of a removed one. They show while the file is on this Device and the speech model or RustO runs there. When nothing comes of it, an announcement at the top says so and its tap tells why; the file stays.

    Remove recording, keep text and Remove photo, keep text, in the editor and in the card's ⋮, do the opposite for a recording or photo that has a text: they ask once ("Remove this recording and keep its Transcript?" or "Remove this photo and keep its Photo Text?"), then the file goes from all your Devices and from everyone you share the Note's Area with, and the text stays on the Note. The card's ⋮ offers them for the Note's own files, the editor also for its Sections'. In a Shared Area a Member does all of this only on their own Notes.

    On the desktop all these buttons are in the Note dialog, under each photo and recording; the card's ⋮ has none of them.

    Search your Notes

    Find Notes by a word in their text, Transcripts, Photo Texts and lists.

  • Tap Search and browse.
  • Type a word into Search all Notes.
    •
  • Press Ctrl+F.
  • Type a word.
    •

    The notes browser has a search field on every level: "Search all Notes" on the Areas list, "Search this Area" and "Search this Topic" below it. The search finds what is typed in any case, in a Note's text and its Sections, its Transcripts and Photo Texts, the text lines of its Tally's entries and the Lines of its Checklist or Shopping List. A formatted text is searched as it reads: "bold" finds "**bold**", and the Markdown marks are found nowhere. A removed Transcript or Photo Text is no longer found.

    On the desktop the search field sits above the list of Notes: "Search all Notes" on All Notes, "Search this Area" on an Area and "Search this Topic" on a Topic; Unsorted, the Trash and the Agenda have none. Ctrl+F, or Edit ▸ Find, puts the cursor into it, into All Notes' where the list shown has none.
