A Note's text can be formatted, be code, and hold tables, boxes and #tags. Voice recordings get a Transcript and photos a Photo Text, both written on the Device; the search finds Notes by all of them. Each box below shows the steps on the phone and on the desktop.

The desktop app does the same with the mouse and the keyboard. A Note opens in the Note dialog with a double-click on its card; the format bar sits above the text field; a table in the text takes Tab and Shift+Tab to the next and the previous cell; and the search field sits above the list of Notes. The details of each box say where the desktop differs.

Format a Note's text

Make words bold, italic or a heading, or make a list, quote, link or code.

  • Long-press the Note's card.
  • Select the words to format.
  • Tap Bold or another button on the format bar.
  • Tap Back.
    •
  • Double-click the Note's card.
  • Click into the text.
  • Select the words to format.
  • Click Bold or another button above the text.
  • Click outside the text.
    •

    The text of a Note and of a Section can be bold, italic or struck through, have two heading levels, bulleted and numbered lists one level in, quotes, links, inline code, code blocks and tables. It is kept as Markdown, exactly as written. A text stays plain until it is first formatted: by a button of the format bar, by a format typed as Markdown, by pasting a text that uses one, or by Formatted text in its Text format badge. A formatted text does not become plain again directly; it can become Code, and Code can become plain (see "Keep a script as code"). Cards, Sections, Sent Items and Backups show it formatted. A Device with Old Brain Fix 0.1 shows the Markdown and cannot change it.

    The format bar.

    The format bar is there in Advanced. In Simple a field has none, while typed Markdown still formats and a formatted text shows formatted.

    On the phone, the format bar sits on the keyboard while the Note editor or Add to Note has it open; the quick note has none, and its Open in the editor opens the Note editor. Its buttons, in this order:

    • ☐: Put in ☐ at the cursor (in the Note editor and in a table's cell; not in Add to Note; see "Tick a box in the text").
    • Bold, Italic, Strike through and Code.
    • H1 and H2: Large heading and Small heading.
    • Bulleted list, Numbered list and Quote.
    • Link, Link to… and Code block.
    • Indent list item and Move list item out.
    • Table.

    The buttons that find no room go into ⋮ at the end of the bar, More formats, which opens at the finger. Bold, italic, strike-through and code work on the selection, or on the word at the cursor when nothing is selected; the line formats work on every line the selection touches. On the phone, Code also makes a code block: of the lines a selection over more than one line touches, or an empty one at an empty line, the cursor in it; in a block it takes the block's fences off. A button shows highlighted while the cursor is in its format. A second tap takes the format off again, except for Link, which asks for the address again, and Table, which goes into the table; Indent list item and Move list item out each move the item one way.

    With Type in two rows on, the default in Settings under "Typing", the top row shows the text formatted, its Markdown marks left out, and the row above the keyboard shows the Markdown of the cursor's line, with ◀ and ▶ to move the cursor. With it off, the field shows the marks dimmed.

    Typing Markdown. A format typed as Markdown takes effect as it is typed:

    • At the start of a line, followed by a space: # for a large heading, ## for a small one, -, * or + for a bulleted item, 1. for a numbered item and > for a quote.
    • Within a line: **bold**, *italic* or _italic_, ~~struck~~, `code` and [label](address).
    • On a line of its own: ``` or ~~~ opens a code block, and the same fence on a later line closes it; typing the closing fence makes a plain text formatted.

    Every line break shows as one, so lines typed one under the other stay apart. An item indented by two spaces or more is one level in; deeper items show one level in. Numbered items that follow one another count on, so 1. on every line shows 1, 2, 3. Deeper headings (###), images and other Markdown show as written.

    On a capture screen without the format bar, a text typed or pasted with Markdown is saved as a formatted text.

    Code blocks.

    A code block is the lines between two fences of three backticks, ```, or three tildes, ~~~, each fence on a line of its own. It shows in a fixed-width font on a light tint, its lines exactly as written: nothing in it is a format, a table, a #tag or a box. A word after the opening fence, such as ```bash, names the language; it is kept in the text but does not show. When the app knows that language, the block is coloured by its syntax (see "Keep a script as code"); a block naming none or another stays in one colour. A block ends only at a fence of the same character at least as long as the one that opened it, so in a block opened with four backticks a line of three is a line of the block. Without a closing fence the block runs to the end of the text.

    Code block in the format bar puts the lines the selection touches into a block, an empty one at an empty line; in a block it takes the block's fences off. Its fences are longer than any run of backticks inside. On a compact card a code block shows its lines without the fences.

    Links.

    Link asks for the "Web or e-mail address", the one there already filled in; Set link puts it on the selection or the word at the cursor. Leave it empty to remove the link. An address typed without "https://" is taken as a web address, or as an e-mail address when it holds an "@" and no "/". A tap on a link on a card opens it in the browser or the mail app. Only web and e-mail addresses and the app's own links open; any other link, which may come from another person in a Shared Area, stays text.

    Link to… links to a place in the app: pick a Note, an Area or Topic, or a page such as the Agenda, Unsorted, the Settings or one of their sections, All Routines and Reminders, Backups, Sync, the Profile, the Frogs, New Session or the user guide, the search above the list finding it. The link goes on the selection or the word at the cursor, or in with the target's name. A tap on it opens the place without asking, on every Device; where the target cannot be seen, such as a Note in the Trash or one never synced here, it says "Not available here". Other Markdown apps show its words. Its address starts with oldbrainfix://, such as oldbrainfix://settings/backups.

    A Note that other Notes link to shows them at its end, after its Sections, under Linked from: one row per Note by its first line, and a tap opens it. It shows in the detailed view of the card, in the Note editor, and on the desktop in the Note dialog and a Note's own window, its reading view too, but not on a compact card or a card in the Trash. Only links to a Note count, in its text or its Sections; Notes in the Trash, of a Shared Area you are no member of and of a locked Area while it is closed are left out. Nothing is stored for it: it is read from the texts.

    A link to a file of the shared folder, such as oldbrainfix://file/Scans/tax.pdf, opens it with the app the phone or computer has for it, after one question naming the file and that app. Files outside the shared folder (on the desktop the synced folder) never open, and the file is not copied into the app. On the iPhone file links do not open yet.

    A web address written into any text, plain or formatted, that starts with "http://" or "https://" is a link too: a tap on it opens it in the browser, and a tap beside it or a long press does what it does on the card. Punctuation right after it, such as a full stop, a comma or a closing bracket, is not part of it; "www." alone is no link. An address in code, a code block, a Code text or a link stays as written. The text itself is not changed.

    On the desktop.

    • The format bar sits above the text field of the Note dialog, with the same buttons; each shows its name as a tooltip. Buttons that find no room go onto a further line. Ctrl+B and Ctrl+I are bold and italic while typing.
    • A right-click on words selected in a formatted text offers the format bar's Bold, Italic, Code, Link and Code block for them, below Cut, Copy, Paste and Select all.
    • A formatted text shows as it reads; a click on it edits its Markdown, the marks dimmed. Leaving the field or Ctrl+Enter saves it.
    • A Markdown task such as - [ ] milk typed in the quick note or Add to Note becomes a box when the text is saved; in the Note dialog it does as the space after ] is typed.
    • Add to Note, which Add a part in the Note dialog opens, has the format bar too, without ☐, which only the Note's text puts in; a table in it is edited in the field as in the Note editor, and nothing is kept before Add to Note.
    • Link opens a dialog with the same field; Enter or Set link takes it. A click on a link opens it in the browser or the mail program; the mouse over it shows its address. A web address written into a text opens on a click too.
    • Link to…, beside Link, opens the same picker with its search; a click on a target puts the link in. A click on an app link opens its place in the window, the Settings at their section, a guide page in the browser.

    Keep a script as code

    Show a Note's whole text exactly as written, such as a script.

  • Long-press the Note's card.
  • Tap the Text format badge.
  • Tap Code.
  • Pick its language under Language.
    •
  • Double-click the Note's card.
  • Click the Text format badge.
  • Click Code.
  • Pick its language under Language.
    •

    A plain Note's whole text can be code, such as a script: it shows exactly as written, in a fixed-width font on a light tint, without wrapping its lines. Nothing in it is a format, a table, a #tag or a box. In the Note editor a long line moves sideways under the finger; on a card it is cut off at the edge, and the editor shows it whole.

    • The Text format badge in the Note editor shows the text's format and switches it between Plain text, Formatted text and Code. A formatted text can become Code, its Markdown kept as written, but not plain again directly; a Code text can become plain or formatted. The badge shows for a Plain Note.
    • When a text pasted into the Note's text looks like a script or code, the editor says "This looks like code." under the text with Keep as code; the cross lets the paste be. Such a paste does not format the text. A text looks like code when it starts with #!/, or when at least half of its three or more lines end in ;, { or }, start with }, or are indented by a tab or four spaces without starting a list item. Capture never asks.
    • A Code text with a language is coloured by that language's syntax: keywords, strings, comments, numbers and the like each in a colour of their own, in the light and the dark look. The languages are Shell, Python, JavaScript/TypeScript, Rust, Dart, Kotlin, Java, C/C++, Go, SQL, JSON, YAML, XML/HTML, CSS and Markdown. The language is kept with the Note and syncs; No language shows it in one colour, and so does a Device that does not know the language. After Keep as code the language its first line names, such as #!/bin/bash, is already picked. The colours come from grammar files the app reads as data; nothing in them runs.
    • More languages come from grammar files of your own, Sublime syntax definitions (.sublime-syntax): in Settings ▸ Code languages, Add grammar… picks the file, and its language is offered under Language and colours code blocks naming it, on all your Devices. Only you see code coloured by it; others in a Shared Area see it coloured by their own grammars. A grammar for a language the app knows replaces the built-in one; Remove brings that back. A file of more than 256 KiB, more than 32 grammars, or a grammar using what the app does not read is refused with what is wrong, and nothing is added.
    • A Code text has no format bar and no ☐. Its ☐ stays a character; a box of a text made Code keeps the state it shows as its character.
    • Search finds the words of a Code text as written. Share and Copy text give it as written, without colours.
    • A Note whose text is Code is no Checklist, Shopping List, Tally or Session; its Kind badge only shows it until the text format is changed back.
    • The Note's History lists each change of the text format.

    On the desktop the Text format badge sits among the Note dialog's badges and opens a dialog with the three choices. A Code text scrolls sideways with Shift and the wheel or its scroll bar; "Keep as code" shows under the text after a paste that looks like code.

    Put a table in a Note

    Keep rows and columns, such as meter readings, in a Note's text.

  • Long-press the Note's card.
  • Tap where the table should go.
  • Tap Table on the format bar.
  • Type into each cell; ↵ goes to the cell below.
  • Tap Save.
    •
  • Double-click the Note's card.
  • Click where the table should go.
  • Click Table above the text.
  • Type into each cell; press Tab for the next.
  • Click Save.
    •

    In the Note editor a table is edited right in the text, with its rows numbered and its columns lettered, pasted Markdown tables too. Table in the format bar puts a new table at the cursor, two empty columns with a header row and one more row, on lines of their own, and edits its first cell.

    • A tap or click on a cell edits it in place. Tab and Shift+Tab go to the next and the previous cell row by row, ↵ to the cell below, and the arrow keys at a cell's edge to the cell beside it. Past the first or the last cell the cursor goes into the text before or after the table, and the arrow keys (on the phone also ◀ and ▶) go from the text into it.
    • While a cell is edited, the format bar holds ☐, bold, italic, strike-through, link and code for its words. A cell holds one line.
    • + under the last row and beside the last column adds a row or a column.
    • A tap or click on a row's number opens Insert a row above, Insert a row below, Move up, Move down and Delete row; a column's letter opens Insert a column to the left, Insert a column to the right, Move left, Move right, Delete column, Align left, Centre and Align right, and for column A the switch First column as headings.
    • Deleting a row or column that holds words asks once, "Delete this row?" or "Delete this column?": "The words in its cells are deleted from the Note." Deleting the last row or column deletes the table, and asks "Delete the table?".
    • Show as lines shows the table's Markdown lines to edit them as text; Show as table, the cursor leaving the lines or leaving the field shows the table again.
    • On the phone, ⋮ at the table's top right corner holds Copy, Move up, Move down and Delete table. Moving takes the whole table past the block of text above or below it: a paragraph, a list, a quote, a heading, a code block or another table. Deleting a table that holds words asks "Delete the table?" first. Undo takes each of them back.
    • A column's letter also offers Sort rows by this column and Sort rows by this column, descending, which put the rows under the header in that order in the Note's text. A column of numbers, also with a unit or a currency sign such as "12,50 €", sorts by number, one of dates by date, any other alphabetically, case and umlauts not counted; empty cells go last. Undo takes it back; rows already in that order change nothing.
    • On the desktop, ⋮ at the table's top right corner in the Note dialog and a Note's own window holds the same Copy, Move up, Move down and Delete table, also while the text is only shown there. Undo in the dialog's bar takes each of them back.

    For the text around it, a table is one block: what is typed right before it goes on a line of its own, and what is typed right after it goes under it with a blank line between. Backspace right after a table, or deleting a selection that holds one, deletes the whole table, and asks first while its cells hold words. On the phone a table wider than the field moves sideways with a drag on it, and the row above the keyboard is hidden while a cell is edited.

    Tables are written as GFM tables: each edit writes the whole table anew, every row as | a | b |, and leaves the words in its cells as they were. Markdown has no column widths: on the desktop a column's border can be dragged to make it wider or narrower, and that width is not kept. A line typed right under a table's Markdown, without a blank line between, becomes a row of it.

    On a card, and where you may only read the Note, a table is drawn as a grid at the size of the text, its header row in bold, a long cell wrapping onto more lines. A table wider than its room moves sideways inside it, the first column staying while it holds headings; on the phone with a drag on its cells or by Move the table sideways above it, on the desktop with the bar under it or Shift and the mouse wheel. Its header row stays in view while its rows scroll. A card shows the first 10 rows under the header; Show all 200 under them shows the rest in place. A tap or click on a table opens it full screen, to edit from the card or only to read. Full screen, the header row stays on screen while the rows scroll, and so does the first column while it holds headings; on the phone a table wider than the screen moves sideways with a one-finger drag on its cells or by Move the table sideways. On the desktop Alt+Left, the mouse's back button, Esc or the arrow at the top leave it. Copy at the top puts the table on the clipboard: an app that takes formatted text, such as a mail or a document, pastes it as a table, any other as its Markdown lines, which paste into a Note as the same table. Each box goes as it shows, ticked or not. On the phone, ⋮ at the top right corner of a table, on a card, in a text being read and full screen, offers the same Copy; a tap on ⋮ opens neither the table nor the Note. A tap or click on a cell of the header row, on a card, in a text being read, on the desktop also in the reading view and the Markdown viewer, and full screen where the table is only read, sorts the rows shown by its column in the same way: ascending, then descending, then as written again, an arrow in that cell showing which. It opens neither the table nor the Note, the Note's text stays as written, and the order is forgotten on leaving; a card then shows the first 10 rows in that order. Full screen where the table is edited, a tap or click on a cell of the header row edits it, and the column's letter offers Show sorted ascending, Show sorted descending and Show as written instead; putting in, moving or deleting a row or column there shows the rows as written again. On the desktop ⋮ beside a table's top right corner offers Copy on a card, in a Section, in the reading view, in the Markdown viewer and full screen; a click on ⋮ opens neither the table nor the Note.

    On the phone a long press on a cell selects it, in a Section's text being read, in the Note editor's table and full screen, but not on a card. Dragging on without lifting the finger selects every cell from there to the one under the finger. Copy above the cells puts them on the clipboard as a table of their own, the first row as its header row, also a single cell; for one cell Search finds its words in the Note. A tap ends the selection. A selection that starts in the text before a table runs through its cells and copies as text.

    On the desktop a drag that starts on a cell selects every cell from there to the one under the pointer, in a text being read, in the reading view, in the Markdown viewer, in the Note editor's table and full screen, but not on a card; Shift+click selects from the cell selected first to the one clicked. Ctrl+C (Cmd+C on macOS) or Copy in the right-click menu puts the cells on the clipboard as a table of their own, in the same way; for one cell Search there finds its words in the Note. A click on the table or Esc ends the selection and does nothing else; a click beside it ends it too. A drag that starts in the text before a table selects its words as text.

    Tick a box in the text

    Mark a point in a text as done or failed, such as "✅ v2 supported".

  • Type ☐ in the text, or tap ☐ on the format bar.
  • Tap Back.
  • Tap the ☐ on the Note's card.
  • Tap Check, Fail or Open.
  • Tap the box again, then History.
    •
  • Type ☐ in the text, or click ☐ above the text.
  • Click outside the text.
  • Click the ☐ on the Note's card.
  • Click Check, Fail or Open.
  • Click the box again, then History.
    •

    A ☐, ✅ or ❌ anywhere in the text of a Note or a Section is a box: open, checked or failed, such as "✅ v2 supported at the customer". It becomes a box when the text is saved, and the character it was written with is the state it starts in. A tap on it opens a menu at the finger with Check, Fail and Open, the current state left out. The choice is kept beside the text with who made it and when, synced to every Device; the text itself stays as it is.

    • A box can stand in the middle of a word or line, in a list item, a quote, a link's words and a table's cell. In inline code, a code block, a link's address or a web address it does not; nor do other boxes and ticks such as ☑ or ✓.
    • Boxes are ticked on the Note's card, in its Sections, in the Note editor and in a table full screen. A box being typed can be ticked once the text is saved.
    • ☐ in the format bar puts ☐ in at the cursor, also in the middle of a word.
    • In a formatted text, a list item written as a Markdown task, such as - [ ] milk or 1. [x] bread, becomes a box: [ ] becomes ☐ and [x] or [X] becomes ✅. This happens as the space after ] is typed, when such a list is pasted, and when a Markdown file is imported. In code, a code block, a Code text or a plain text it stays as written.
    • Each box carries an id that is never seen. The cursor steps over a box as one character; deleting the box's character deletes the box.
    • Show ticks, in the ⋮ of the Note's card and as a badge in the Note editor while the Note or a Section holds a box, shows after each ticked box, small and grey, who ticked it last and when, such as "Ann, Tue 14:02", or "You" for your own ticks; an older tick shows its date. It is kept for that Note on that Device.
    • Once a box has been ticked, its menu also has History: every change, the oldest first, with its state, who made it and when.
    • In a Shared Area everyone with a role there ticks every box of every Note and Section. Adding, moving and deleting boxes is an edit of the text, which stays with the Note's author and the Managers. A Note in the Trash is not ticked; where you may not tick, the menu of a box ticked before holds only History.
    • Copies, shares, Markdown files and Sent Items show each box in its state now. Copy as text, Share and Save as Markdown write a list item of a formatted text that starts with a box as a Markdown task, so other Markdown apps show a checkbox: ☐ as - [ ], ✅ as - [x], and ❌ as - [x] with the rest of the item struck through. The formatted copy beside it shows the boxes as they are.

    On the desktop a click on a box opens its menu under it, also in the field being edited: ☐ Open, ✅ Check and ❌ Fail, the current state left out, and, once it has been ticked, History. In the field being edited the arrow keys step over a box as one character, and Backspace after it or Delete before it removes it with its id. Show ticks is in the card's ⋮ and, in the Note dialog, a badge with a switch.

    Find Notes by a #tag

    Mark Notes with a word such as #garden and find them all again.

  • Type # and a word into a Note's text, such as #garden.
  • Tap the #tag on a card.
    •
  • Type # and a word into a Note's text, such as #garden.
  • Click the #tag on a card.
    •

    A word with "#" in front, such as "#garden", is a tag and is drawn in the accent colour, on cards, in Sections and in the editor. A tap on it on a card, in a Section or in a table opens the search of all Notes with the tag as written. Nothing is stored for a tag; it is a word of the text, and the tag tree lists every tag (see "Browse your #tags"). Typing the tag into the search finds the same.

    • A tag is made of letters, digits, "_" and "-", and holds at least one letter: "#to-do" and "#v2" are tags, "#126" is a number.
    • A "/" nests a tag: "#life/health/back" is one tag, below "#life/health" and "#life". The search for "#life" finds it too.
    • "# Title" with a space, "C#" and the "#" in a web address are no tags. In a formatted text, a "#word" inside code, a code block or a link's address is none either; nor is any in a Code text.
    • The search for "#garden" finds every Note holding it in any case, also "#gardening", which begins with it, but not the word "garden" without "#".

    On the desktop a tag's click closes the Note dialog and searches all Notes, as on the phone; in the field being edited it places the cursor.

    Browse your #tags

    See every #tag of your Notes by its levels, such as #life/health below #life.

  • Tap Search and browse.
  • Tap All tags… at the end of the tags under the search.
  • Tap the arrow beside a tag for the tags below it.
  • Tap a tag to search for it.
    •
  • Click All Notes in the sidebar.
  • Click All tags… at the end of the tags under the search.
  • Click the arrow beside a tag for the tags below it.
  • Click a tag to search for it.
    •

    The tag tree lists the #tags of every Note and its Sections, the top level as written ("#life"), each level below by its own word ("health"), indented, with how many Notes carry the tag or a tag below it. At first only the top level shows; the arrow beside a tag unfolds the levels below. A tap on a tag goes back to the Areas list and searches for it there. A tag written in several ways ("#Life", "#life") shows as most of its Notes write it.

    While the search of the Areas list is empty, one row under it shows the most used tags as buttons, at most twelve, those on the most Notes first, and ends in All tags…. A tap on a tag searches for it. A row wider than the screen moves sideways under the finger.

    Typing "#" into the search of the Areas list shows the tags that start with what is typed as buttons under the field, at most twelve; a tap fills one in, so a tag is found without knowing its exact spelling. While a locked Area is closed, the tags of its Notes are left out of the row of tags, the tag tree and these buttons, as its Notes are left out of every list.

    On the desktop the row of the most used tags sits under the search of All Notes, while it is empty; a click on a tag searches for it there, and All tags… shows the tag tree in the list. A row wider than the window leaves out the least used tags. A click on a tag in the tree shows All Notes searching for it. Typing "#" into the search of a list, but the Trash's, shows the tags that start with what is typed as buttons under the field, at most twelve; a click fills one in. The desktop has no Area Locks, so it leaves no tag out.

    Get the words of a voice recording

    Let the app write down what a voice recording says, as its Transcript.

  • Tap your Profile picture, then Settings.
  • Tap Speech model.
  • Tap Base, 148 MB.
  • Record a voice Note.
    •
  • Click Edit ▸ Settings….
  • Click Base, 148 MB under "Speech model".
  • Record a voice Note.
    •

    A voice recording gets a Transcript: the words recognised in it, kept next to the recording. Whisper writes it on the Device, in English or German, whichever the recording sounds more like, in the background and one recording at a time once the Note is saved; recordings captured before the speech model was there follow. While it runs, "Transcribing…" shows under the recording; a recording without speech shows "No words heard.". On the phone's quick note the Transcript also goes into the text once it is done (see Capture and sort). The recording is always kept.

    Whisper is led in with your Area and Topic names; for German speech also with the English words German is full of and the app's words, such as Unsorted, Routine and Agenda, so that they are written as they are spelt. Where Whisper only repeats that lead-in, or a run of three or more of those names, the repeat is taken out of the Transcript.

    The speech models.

    Transcripts need a speech model, downloaded once. The phone offers it after the first start (see Getting started); Settings, Speech model offers it on the phone and the desktop at any time. Under "Model":

    • Base, 148 MB: faster, and enough for English or German alone.
    • Small, 488 MB: better with English words in German speech, but slower, and it needs more memory.

    Choosing a model downloads it, with its progress and Cancel. Only the chosen model is kept: the one before is deleted once the new one is in place. Each download comes only from Old Brain Fix's own release on GitHub and is checked against a fixed checksum before it is used; a download that broke off or did not match keeps nothing and says so. Use a file of my own takes whisper.cpp's multilingual ggml-base.bin or ggml-small.bin from the Device, known by its checksum, whatever the file is called; any other file is rejected.

    On the desktop the speech model is a card in the Settings dialog, after "Quick note", with the same choices; Transcripts work the same, while the app runs.

    On the iPhone, a voice message shared into the app on an Android phone as an Ogg file, as WhatsApp sends them, neither plays nor gets a Transcript: iOS reads no Ogg. Recordings made in Old Brain Fix play on every Device.

  • Press Ctrl+N, or click File ▸ New Note.
  • Press Ctrl+V, or click File ▸ Attach a file…, for the photo.
  • Click 10 min, 30 min or 1 h.
  • Double-click the Note's card.
  • Read the Photo Text under the photo.
    •

    A photo or a picture gets a Photo Text: the text recognised in it, kept next to the photo. RustO reads it on the Device with PaddleOCR's PP-OCRv6 Tiny models, which are part of the app, so nothing is downloaded and nothing leaves the Device. It reads German letters (ä, ö, ü, ß) and €, and keeps the lines as they are laid out on the photo, so a price stays on the line of its item. A strongly curved page can lose some of its lines. Photos are read in the background, one at a time, once the Note is saved; capturing never waits for it.

    In a card's detailed view, Transcripts and Photo Texts show dimmed under the word "Transcript" or "Photo Text". The compact view of a Note without words shows the first three lines of its Transcripts, and of the Photo Texts of photos that were removed; a photo still there shows as a small picture. While none of its Transcripts has words, the first line of a photo's Photo Text shows above the pictures as the Note's name.

    On the desktop Photo Texts work the same, while the app runs; the Note dialog shows each one under its photo.

    Attach a file to a Note

    Keep a letter, a contract or any other file with the Note it belongs to.

  • Tap + on the Agenda.
  • Tap File.
  • Pick one or more files.
  • Tap 10 min, 30 min or 1 h.
  • Tap the file on its card to open it.
    •
  • Drag one or more files onto the window.
  • Press Ctrl+Enter.
  • Click the file on its card to open it.
    •

    Any file can be attached: a PDF, a Word document, a spreadsheet, a .zip. It is kept as it is, with its name, type and size, on all your Devices and with everyone you share the Note's Area with. Besides File in Capture and in the fan of +, a file comes in by sharing it from another app to Old Brain Fix, and by Attach a file under Add at the end of the Note editor. A file larger than 256 MB is not attached, and the app says so at the top. A Note made from one file alone shows the file as its card and goes by its name, also in alarms. A tap on a PDF shows it in the app; a tap on any other file opens it with the app of the phone that opens that kind. A file that has not synced to the phone yet, or that no app opens, is said at the top. An Android app (.apk) asks "Open it anyway?" first, naming who added it when another person did.

    A PDF shows full screen, as a photo does. Swipe sideways to turn its pages and spread two fingers to zoom in; a zoomed page moves under the finger and turns again once it is back at its size. "Page 2 of 12" at the top says which page shows. The Attachment Text button at the top shows the text read out of the PDF instead of its pages, and a second tap shows the pages again. Open in another app in its ⋮ hands it to the phone's app for PDFs. Back closes it. A PDF the phone cannot show, such as one locked with a password, opens with the phone's app for PDFs instead. Word, Excel and other files open with the phone's app for them.

    The text of a file is read out where its format allows: a PDF's own text and, through the same text recognition as for photos, its scanned pages; .docx, .odt, .xlsx and .ods files; plain text and Markdown. This Attachment Text shows dimmed under the file, under the words "Attachment Text", and the search finds it and the file's name. The phone reads a PDF of up to ten pages and other files up to 10 MB itself, in the background. A longer PDF, or a larger file, is left to your computer: until it has read the file and the text has synced back, the phone shows "The text follows from the computer." Other files, such as a .zip, have no text.

    In the Note editor, under each file: Replace Note text and Append to Note text take its text in, Remove generated text removes the text (the announcement at the top brings it back), Read the text again reads it anew, and Remove Attachment, keep text asks once and removes the file from all your Devices while its text stays. The card's ⋮ offers the last too.

    On the desktop, a file dropped onto the window waits in the quick note and is saved with what is typed as one Note; dropped onto the Note dialog, it goes onto that Note. File ▸ Attach a file…, and Attach a file… under Add in the Note dialog pick files in the system's dialog. A click on a file opens a copy of it with the program the computer has for its kind; one that has not synced to the computer yet, or that no program opens, is said at the top. A file that could run a program, such as an .exe, a script or a shortcut, asks "Open it anyway?" first, naming who added it when another person did; documents, pictures, sound, video and .zip files open at once. The computer reads the text of every file waiting, a longer PDF or a larger file left to it by a phone too, in the background, and the text syncs back to the phone. A file whose text cannot be read gets none and is not read again until Read the text again. The Note dialog has the same buttons under each file as the phone's editor; Remove generated text is taken back with Ctrl+Z or Edit ▸ Undo.

    Print a page into a Note

    Keep a page from an app that does not let you share or copy it.

  • Tap your Profile picture, then Settings.
  • Tap Open print settings and turn on Old Brain Fix.
  • Tap Print in the other app.
  • Pick Old Brain Fix as the printer and tap the print button.
  • Tap 10 min, 30 min or 1 h.
    •
  • Print the page as a PDF in the other program.
  • Drag the PDF onto the Old Brain Fix window.
  • Press Ctrl+Enter.
    •

    Some apps, such as banking apps, document viewers and company tools, block sharing and copying, but nearly every app can print. On Android, Old Brain Fix is a printer: printing to it opens Capture with the printed pages attached as a PDF, named after the document, for example "Statement March.pdf", the same as when a PDF is shared to the app. Type, file the Note or set a Reminder as usual; leaving saves it with the Nudge in 1 h. Its text is read as for any attached PDF: the phone reads up to ten pages, and a longer PDF is read by your computer, whose text then syncs back. Android does not tell which app printed, so the Note's Capture Context names no app.

    Settings ▸ Capture ▸ Print to Old Brain Fix says whether the printer is on. Where the row already says On, there is nothing to turn on. Android keeps that switch in its own print settings, on many phones under Connected devices ▸ Connection preferences ▸ Printing; an app cannot turn it on itself. Where Android does not say whether it is on, the row says how to turn it on. Where Android does not let the app come up by itself, the printed pages wait, and Capture opens with them the next time you open the app.

    The iPhone has no printers of other apps. Tap Print, spread the preview with two fingers so it opens as a PDF, then tap Share ▸ Old Brain Fix. A small card says the PDF was kept, and Capture opens with it the next time the app opens or comes back.

    On the computer, the system's print dialog saves a page as a PDF: "Microsoft Print to PDF" on Windows, PDF ▸ "Save as PDF" on macOS, "Print to File" on Linux. Dropped onto the window, the PDF waits in the quick note like any other file.

    Use or remove a Transcript or Photo Text

    Take a Transcript or Photo Text into the Note's text, or remove it.

  • Long-press the Note's card.
  • Tap Replace Note text or Append to Note text.
  • Tap Remove generated text instead.
    •
  • Double-click the Note's card.
  • Click Replace Note text or Append to Note text.
  • Click Remove generated text instead.
    •

    Only the app writes a Transcript or Photo Text; it cannot be edited. In the Note editor, under each Transcript and Photo Text, also those of a merged Note's Section:

    • Replace Note text makes it the text; Append to Note text adds it on a line of its own after the text. Under a Section's Transcript or Photo Text they change that Section's text. The text is then edited as usual. Into a formatted text it goes as plain text, written so that it reads as itself. Both show while the generated text has words and the text may be changed.
    • Remove generated text asks nothing. On the phone the announcement at the top, "Transcript removed" or "Photo Text removed", brings the text back with a tap; on the desktop Ctrl+Z or Edit ▸ Undo does. Then the search no longer finds the text, on all your Devices, and the recording or photo stays, so the text can be made from it again. The text of a recording or photo removed with an earlier version stays under it and cannot be removed; it is all that is left of it.
    • Transcribe again and Read the text again make the text anew from the file, in place of the one before or of a removed one. They show while the file is on this Device and the speech model or RustO runs there. When nothing comes of it, an announcement at the top says so and its tap tells why; the file stays.

    Remove recording, keep text and Remove photo, keep text, in the editor and in the card's ⋮, do the opposite for a recording or photo that has a text: they ask once ("Remove this recording and keep its words in the text?" or "Remove this photo and keep its words in the text?"), then the file goes from all your Devices and from everyone you share the Note's Area with. Its text goes into the Note's text as a paragraph of its own, after a blank line, or becomes the text when the Note has none; it is then edited or deleted like typed text, and no Transcript or Photo Text is left. The card's ⋮ offers them for the Note's own files, the editor also for its Sections'. In a Shared Area a Member does all of this only on their own Notes.

    On the desktop all these buttons are in the Note dialog, under each photo and recording; the card's ⋮ has none of them. There Ctrl+Z or Edit ▸ Undo takes a removed file's words out of the text again, unless the text was empty; the file stays gone.

    Search your Notes

    Find Notes by a word in their text, Transcripts, Photo Texts and lists.

  • Tap Search and browse.
  • Type a word into Search all Notes.
  • Tap a place found under a card.
    •
  • Press Ctrl+F.
  • Type a word.
  • Click a place found under a card.
    •

    The notes browser has a search field on every level: "Search all Notes" on the Areas list, "Search this Area" and "Search this Topic" below it. On the phone it scrolls away with the list and comes back as soon as the list is scrolled up a little; while it has the cursor or a search, it stays. The top bar and the band under it share a colour set off from the page, with a line under the band, and the Notes go under it. The search finds what is typed in any case, in a Note's text and its Sections, its Transcripts and Photo Texts, the names and Attachment Texts of its files, the text lines of its Tally's entries and the Lines of its Checklist or Shopping List. A formatted text is searched as it reads: "bold" finds "**bold**", and the Markdown marks are found nowhere. A removed Transcript or Photo Text is no longer found.

    On the phone each card of a search lists the first three places found in its Note, over its text in the detailed view and under it in the compact one, each with its line and the word on a tint, then "+2 more". A tap on a place opens the Note there, a tap on the card at its first place; a table holding a place shows all its rows. The opened Note shows every place on a tint, and under its top bar the find bar: "3 of 12", ↑ and ↓ to the place before and after, the words editable there, and ✕ to close it; leaving the Note closes it too. It finds in the text being edited as in one only read. The magnifier in the Note's top bar opens the find bar without a search. Case, accents and umlauts do not matter: "muller" finds "Müller", "strasse" finds "Straße"; a typo finds nothing.

    Words selected in a Note with a long press show a small toolbar just above them: Copy, Paste where the text may be changed and something was copied, and Search, which opens the find bar with those words. A long press on an empty spot of the text shows only Paste. Search all Notes in the find bar, between ↓ and ✕, searches every Note for its words; back returns to the Note.

    On the desktop the search field sits above the list of Notes: "Search all Notes" on All Notes, "Search Unsorted" on Unsorted, "Search this Area" on an Area, "Search this Topic" on a Topic and "Search the Trash" in the Trash, which also finds its Routines, Reminders and Frogs by their Note; the Agenda has none. Ctrl+F, or Edit ▸ Find, puts the cursor into it, into All Notes' where the list shown has none. Down in the field goes to the first card found.

    Under each card of a search the desktop lists the first three places found in its Note, each with its line and the word on a tint, then "+2 more", which opens the Note at the fourth. A click on a place opens the Note there; opening the card, by a double-click, Edit or Enter, opens it at its first place. A table holding a place below its first rows shows all of them on the card. The Note dialog shows every place on a tint, the current one stronger, and above the Note the find bar: "3 of 12", the arrows to the place before and after, Enter and Shift+Enter in its field too, the words editable there, Search all Notes, which searches All Notes for the words in the main window, closing the Note dialog, and ✕ to close it; Esc closes it before the Note, and leaving the Note closes it too. With a Note open in the Note dialog or in a window of its own, its reading view included, Ctrl+F or Edit ▸ Find opens the find bar without a search, or puts the cursor back into it; a right-click on words selected in the Note, then Search, opens it with those words.
